# Notion Stock Price Updater

每日自动更新 Notion 股票数据库：收盘价、MA20/50/200、阶段判定、触发信号。

## 架构

```
GitHub Actions (cron 周一~五 UTC 22:00 / 北京 06:00)
  → yfinance 拉收盘价 + 历史数据（带重试）
  → 计算 MA20 / MA50 / MA200 / ATR
  → 判定阶段 + 触发信号（事件类信号基于最近5个交易日窗口，而非单日快照）
  → 读取 Notion 数据库实际字段结构，过滤掉不存在的字段
  → Notion API 写回数据库
```

## Notion 数据库字段要求

| 字段名 | 类型 | 说明 |
|--------|------|------|
| ticker | Title 或 Text | 股票代码，如 AAPL、MSFT |
| 价格 | Number | 收盘价 |
| MA20 | Number | 20日均线 |
| MA50 | Number | 50日均线 |
| MA200 | Number | 200日均线 |
| 阶段 | Select | 自动判定 |
| 触发信号 | Multi-select | 客观信号组合 |
| 价格更新时间 | Date | 脚本**执行**的时间（UTC） |
| 数据日期 | Date | 该收盘价对应的**实际交易日**（新增，见下方说明） |

> `数据日期` 是新增字段，如果你的数据库里还没有这一列，脚本会自动跳过该字段的写入并在日志里打印一次警告，
> 不会影响其余字段的正常更新。建议手动加上这一列（Date 类型），因为它和"价格更新时间"含义不同——
> 后者是"脚本什么时候跑的"，前者是"这个收盘价实际对应哪个交易日"。如果 yfinance 某次返回的是稍早的缓存数据，
> 两者会不一致，这个字段能帮你识别数据是否新鲜。

## 阶段标签

**事件类**（优先级最高，基于最近 5 个交易日窗口检测，而不是只看"昨天 vs 今天"——
避免 workflow 因故停跑几天后，重新跑起来时把窗口期内已经发生过的突破/金叉事件永久错过）：

1. **突破MA200（拐点）** — 最近5个交易日内，收盘价上穿 MA200
2. **突破MA50（启动）** — 最近5个交易日内，收盘价上穿 MA50
3. **反转确认（金叉）** — 最近5个交易日内，MA50 上穿 MA200，且当前收盘价仍在 MA50 上方

**趋势类：**

4. **右侧上行** — Close > MA50 且 > MA200（无近期事件时的稳态）
5. **突破回踩（健康）** — 右侧上行中，价格回踩到 MA20/MA50 附近

**弱势类：**

6. **左侧下行** — Close < MA20，且 MA20 < MA50 < MA200
7. **跌破MA200（走弱）** — 长期趋势转弱
8. **承压反弹** — 弱势中短线反弹到 MA20 附近/上方

**兜底：**

9. **震荡整理** — 以上都不满足
10. **数据不足 / 数据不足（偏多）** — 上市时间太短，MA50/MA200 尚未形成

## 触发信号集合

- 多头排列 / 空头排列
- 站上MA50 / 站上MA200
- 跌破MA50 / 跌破MA200
- 回踩MA20 / 回踩MA50 / 回踩MA200 —— **回踩阈值基于 ATR 动态计算**（相对价格的 ATR% × 0.6，
  并夹在 1%~5% 之间），不再是固定 2%，高波动股和低波动股用同一套固定阈值会分别导致"天天触发"或"永远抓不到"
- 放量 —— 当日成交量相对前20日均量（不含当日）放大 1.5 倍以上时触发

## 已知设计取舍（暂未实现，故意留白）

- **阶段确认的"持续性"过滤**：均线绞在一起的震荡市里，阶段标签可能逐日来回横跳（比如"震荡整理"↔"承压反弹"）。
  理论上可以要求某个新阶段连续 N 天成立才正式切换，但这需要引入跨次运行的状态记忆（读取 Notion 里上一次的阶段值/维护一个确认计数字段），
  逻辑复杂度和出错面都会明显上升，这次没有把握能在没有真实环境测试的情况下把状态管理写对，所以先不做，留作后续单独迭代。
- **放量与突破的组合判定**：目前"放量"是独立触发信号，没有强制要求"放量+突破同一天"才算数。如果想跟
  `slope-stock-radar` 的"交易突破需放量确认"口径对齐，可以后续把两者绑定，但需要先统一两个项目对"突破"的定义。

|-----------|------|
| `NOTION_TOKEN` | Notion Integration Token |

## 手动触发

Actions → Update Notion Stock Prices → Run workflow

## 维护提示

本仓库是 public repo，GitHub 规定 **超过60天无 commit/PR/issue 活动，定时任务会被自动静默禁用**（不报错，就是不再触发）。
建议每隔一两个月随手 commit 一次（比如更新这份 README 的日期），或者后续加一个自动保活机制。
